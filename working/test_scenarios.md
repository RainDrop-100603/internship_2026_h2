# Mini PS 테스트 시나리오

## 1. 준비

- 유효한 사원·고객사·작업장·코드와 템플릿 연결/미연결 프로파일을 준비한다.
- 각 시나리오는 독립된 테스트 프로젝트로 진행한다. 상태 변경 후에는 재조회하여 저장 결과를 확인한다.
- 정상 화면으로 만들 수 없는 상태 조합·잘못된 참조는 테스트 전용 데이터나 서비스 요청으로 검증한다. 운영 데이터는 변경하지 않는다.

## 2. 프로세스별 테스트

### PS-01 기준정보 등록

| ID | 시나리오·수행 내용 | 기대 결과 | 
|---|---|---|
| TS-01 | 사원·고객사·자재·작업장을 각각 등록하고 이름 수정 후 검색 | 고유 ID 자동 생성, 수정값 저장, ID·이름 검색 결과 일치 |
| TS-02 | 이름 누락 또는 존재하지 않는 참조 코드를 지정해 저장 | 오류 안내, 저장되지 않음 | 

### PS-02 프로젝트 생성·조회

| ID | 시나리오·수행 내용 | 기대 결과 | 
|---|---|---|
| TS-03 | 템플릿 연결 프로파일 선택 후 기본 선택된 적용 옵션으로 생성 | 프로젝트·WBS CRTD, 새 WBS ID와 부모 관계 생성, Activity는 생성되지 않음 |
| TS-04 | 템플릿 적용을 해제하여 생성. 템플릿 미연결 프로파일로도 생성 | WBS 없이 프로젝트 생성. 미연결 프로파일은 적용 옵션 비활성 |
| TS-05 | 필수값 누락, 유효하지 않은 PM·발주처, 시작일>종료일로 각각 저장. 선박 타입 필수/선택 프로파일에서 선박 타입을 비우고 저장 | 잘못된 입력은 차단. 선박 타입은 필수 프로파일에서만 누락 차단 | 
| TS-06 | 프로젝트 ID·명·상태로 검색하여 상세 진입. CRTD·REL에서 허용 기본정보 수정 | 검색·상세 정보 일치, 수정 저장 가능. 프로파일·선박 타입은 변경 불가 |

### PS-03 WBS 구성

| ID | 시나리오·수행 내용 | 기대 결과 |
|---|---|---|
| TS-07 | 빈 프로젝트에서 최상위 WBS 등록 후 하위 WBS 추가·이름 수정 | 최상위 부모 없음·Level=1, 하위 Level=부모+1, 초기 CRTD, 트리에 반영 | 
| TS-08 | 다른 프로젝트 부모·자기 자신·자손을 부모로 지정하거나 저장된 부모 변경 요청 | 잘못된 구조 및 부모 변경 차단 | 
| TS-09 | 프로젝트·대상 WBS·상위 WBS 중 하나가 TECO/CLSD인 범위에서 WBS·Activity 등록/수정 | 완료 범위의 변경 차단. 다른 정상 범위는 영향 없음 | 

### PS-04 Activity 계획

| ID | 시나리오·수행 내용 | 기대 결과 | 
|---|---|---|
| TS-10 | CRTD·REL 범위의 WBS에 Activity 수동 등록. 하위 WBS가 있는 노드에도 등록 | PLAN으로 저장, 선택 WBS에 연결, 말단 여부로 제한하지 않음 | 
| TS-11 | 이름·작업장·담당자 누락, 잘못된 참조, 시작일>종료일로 각각 저장. 유효한 프로젝트 기간 밖 일정도 저장 | 잘못된 입력은 차단. 시작일≤종료일인 프로젝트 기간 밖 일정은 허용 | 

### PS-05 프로젝트·WBS Release

| ID | 시나리오·수행 내용 | 기대 결과 | 
|---|---|---|
| TS-12 | 프로젝트와 상위 WBS가 CRTD인 상태에서 하위 WBS만 Release | 선택 WBS와 전파 가능한 하위 CRTD만 REL. 프로젝트·상위·Activity 상태 유지 |
| TS-13 | 프로젝트 CRTD, A TECO, A의 자식 B CRTD, 별도 C CRTD 상태에서 프로젝트 Release | 프로젝트·C만 REL. A와 그 아래 B는 유지, 팝업 변경 건수에서도 제외 | 
| TS-14 | 하위 변경 대상이 있는 Release에서 취소/확인을 각각 수행. WBS 0건 프로젝트도 Release | 취소 시 전체 유지, 확인 시 일괄 변경. 하위 변경 0건은 전파 확인 팝업 없이 REL | 
| TS-15 | TECO/CLSD 상위 아래 WBS를 직접 Release하거나 REL 대상을 다시 Release | 허용되지 않는 변경 차단, 상태 유지 |

### PS-06 작업 실행

| ID | 시나리오·수행 내용 | 기대 결과 |
|---|---|---|
| TS-16 | 직속 WBS REL에서 PLAN→PROC→HOLD→PROC→COMP 수행 | 각 전이 저장. 프로젝트·상위 WBS가 CRTD여도 가능. WBS 자동 TECO 없음 | 
| TS-17 | PLAN→COMP, COMP→PROC 요청. 직속 WBS CRTD에서 착수 요청 | 전이 또는 WBS 상태 검증으로 차단 | 
| TS-18 | 직속 WBS TECO에서 PROC 완료, PLAN 착수, PROC 보류, HOLD 재개를 각각 요청 | PROC→COMP만 허용. 나머지는 차단 | 

### PS-07 기술 완료

| ID | 시나리오·수행 내용 | 기대 결과 |
|---|---|---|
| TS-19 | REL WBS를 수동 기술 완료. 하위에 CRTD와 그 아래 REL을 두고 실행 | 대상·전파 가능한 하위 REL만 TECO, CRTD는 유지·잠금. 기존 TECO/CLSD 아래는 제외, 상위 상태 유지 | 
| TS-20 | PLAN·PROC·HOLD 작업 및 새로 잠기는 CRTD WBS가 있는 범위에서 기술 완료 후 취소/확인 | 미완료 작업과 잠기는 WBS를 구분해 경고. 빈 CRTD WBS도 표시. 취소는 전체 유지, 확인은 Activity 상태 보존 | 
| TS-21 | Activity 0건인 REL WBS·프로젝트를 각각 기술 완료. CRTD 대상에도 요청 | Activity 0건이어도 REL 대상은 TECO 가능, CRTD 대상은 차단 |

### PS-08 프로젝트 종료

| ID | 시나리오·수행 내용 | 기대 결과 | 
|---|---|---|
| TS-22 | 프로젝트 TECO 아님, PROC Activity 남음, REL WBS 남음을 각각 준비해 종료 | 각 조건에서 종료 차단. PROC는 TECO WBS에서 완료한 뒤 재요청 가능 | 
| TS-23 | PLAN·HOLD Activity 또는 CRTD WBS가 남은 TECO 프로젝트 종료. 사유 공백·미동의·유효 입력을 각각 확인 | 목록·건수 표시. 공백/미동의 차단, 유효 입력과 확인 시 종료. 빈 CRTD WBS도 사유 필요 | 
| TS-24 | PROC·REL·미수행 범위가 없는 TECO 프로젝트를 사유 없이 최종 확인. WBS·Activity 0건도 확인 | 종료 성공. Project·TECO WBS는 CLSD, 기존 CLSD 유지. 사유는 선택 | 
| TS-25 | 미수행 범위 마감 후 상태·이력 조회 및 수정·상태 변경 요청 | CRTD·TECO WBS는 CLSD, Activity 상태 보존. 사용자·시각·사유·대상 상태 이력 조회 가능, 업무 변경 차단 | 
| TS-26 | 개별 WBS의 CRTD→CLSD를 요청. 프로젝트 종료 확인 팝업에서는 취소 | 개별 예외 전이 차단. 종료 취소 시 상태·이력 변경 없음 | 

## 3. 공통 예외 테스트

| ID | 시나리오·수행 내용 | 기대 결과 |
|---|---|---|
| TS-27 | 조회 결과 0건과 조회 오류를 각각 발생. 변경 입력 후 취소 요청 | 결과 없음과 오류를 구분해 안내. 입력 취소 시 확인 팝업 표시 |
