# Claude-Codex Coding Workspace 구현 및 사용 가이드

## 1. 개요

이 프로그램은 Claude와 Codex를 하나의 로컬 웹 콘솔에서 사용하는 멀티 에이전트 코딩 도구이다.

- **Claude**: 사용자의 작업 지시를 받아 코드를 구현하거나 리뷰 결과를 반영한다.
- **Codex**: Claude가 만든 변경사항을 읽기 전용으로 검토한다.
- **사용자**: diff와 리뷰를 확인한 뒤 수정 요청, 승인 또는 반려를 결정한다.

핵심 목표는 구현과 검토 역할을 분리하고, 승인되지 않은 변경이 원본 프로젝트에 바로 반영되지 않도록 하는 것이다.

## 2. 전체 구성

| 영역 | 구현 기술 | 역할 |
| --- | --- | --- |
| 프론트엔드 | React, Vite | 프로젝트·작업 관리, 로그, diff, 리뷰, 사용량 표시 |
| 백엔드 | Node.js, Express | 프로젝트 및 작업 상태 관리, API 제공 |
| 실시간 통신 | WebSocket | Claude 로그와 작업 상태를 화면에 실시간 전달 |
| Claude 연동 | Claude Agent SDK | 코드 구현 및 리뷰 반영 수정 |
| Codex 연동 | Codex CLI | 고정된 Git 커밋 범위의 코드 리뷰 |
| 변경 격리 | Git worktree | 원본 프로젝트와 분리된 임시 작업 공간 제공 |
| 상태 저장 | 로컬 JSON | 프로젝트, 작업, 설정, 리뷰 스냅샷 저장 |

주요 폴더는 다음과 같다.

```text
2_통합콘솔/
├─ backend/       API, 작업 관리, Git 및 에이전트 연동
├─ frontend/      React 웹 화면
├─ scripts/       백엔드·프론트엔드 통합 실행
├─ test-scripts/  실제 작업 흐름 확인용 스크립트
├─ docs/          보안 관련 문서
├─ start.bat      Windows 실행 파일
└─ package.json   백엔드 실행 및 테스트 설정
```

실행 중 생성되는 `.runtime`, `frontend/.env.local`, `node_modules`, `dist`는 소스가 아니라 로컬 실행 데이터 또는 빌드 결과물이다.

## 3. 작동 방식

### 3.1 프로그램 시작

1. `start.bat` 또는 `npm start`를 실행한다.
2. 백엔드가 `127.0.0.1:4317`에서 시작된다.
3. 백엔드는 시작할 때마다 새로운 nonce 토큰을 발급한다.
4. 실행 스크립트가 접속 주소와 토큰을 `frontend/.env.local`에 기록한다.
5. Vite 개발 서버가 시작되고 `http://localhost:5173`이 브라우저에서 열린다.
6. 웹 화면은 발급된 토큰을 API와 WebSocket 요청에 사용한다.

### 3.2 프로젝트 등록

1. 상단의 `+ 새 프로젝트`를 선택한다.
2. 프로젝트 이름과 Git 저장소의 절대 경로를 입력한다.
3. 백엔드는 경로와 `.git` 존재 여부를 확인한 후 프로젝트를 등록한다.
4. 등록 정보는 `.runtime/projects.json`에 저장된다.

프로젝트 등록은 기존 폴더를 콘솔 목록에 연결하는 동작이다. 콘솔에서 프로젝트를 제거해도 실제 프로젝트 폴더나 Git 저장소는 삭제되지 않는다.

### 3.3 Claude 구현

사용자가 작업 지시를 보내면 다음 순서로 처리된다.

1. 현재 프로젝트 브랜치와 시작 커밋 SHA를 기록한다.
2. `.runtime/worktrees/<task-id>`에 임시 Git worktree를 만든다.
3. `task/<task-id>` 형식의 임시 브랜치를 생성한다.
4. Claude Agent SDK를 임시 worktree에서 실행한다.
5. Claude의 메시지와 도구 실행 결과를 WebSocket으로 화면에 전달한다.
6. 작업 완료 후 모든 변경을 임시 브랜치에 커밋한다.
7. 기준 커밋부터 결과 커밋까지의 diff와 해시를 저장한다.

따라서 Claude가 작업하는 동안에는 원본 프로젝트의 파일과 브랜치가 직접 변경되지 않는다.

### 3.4 Diff 확인

Claude 작업이 끝나면 화면 하단에서 다음 내용을 확인할 수 있다.

- 변경된 파일 목록
- 파일별 추가·삭제 라인
- 변경 파일 수와 diff 통계
- 작업에 사용한 모델과 effort
- 입력, 캐시, 출력, 추론 토큰 사용량
- Claude SDK가 제공하는 예상 비용

사용자는 `작업 폴더 열기`를 눌러 임시 worktree에서 코드를 직접 실행하거나 테스트할 수도 있다.

### 3.5 Codex 리뷰

`Codex 리뷰 요청`을 누르면 Codex는 Claude가 만든 결과를 검토한다.

리뷰 대상은 작업 시작 시점의 `baseSha`와 Claude 작업 완료 시점의 `targetSha`로 고정된다. Codex에는 diff 전체를 프롬프트에 첨부하지 않고 커밋 범위와 원래 작업 요청을 전달한다. Codex가 worktree에서 필요한 diff와 주변 코드를 직접 읽기 때문에 큰 변경에서도 불필요한 프롬프트 토큰 사용을 줄일 수 있다.

리뷰 실행 시에는 다음 안전장치를 사용한다.

- Codex CLI를 읽기 전용 샌드박스로 실행한다.
- 리뷰 전후에 worktree의 HEAD와 변경 상태를 확인한다.
- `baseSha..targetSha` 범위가 바뀌면 작업을 중단한다.
- 결과는 JSON Schema에 맞춰 파일, 라인, 심각도, 내용을 구조화한다.
- 리뷰 결과와 사용량은 작업 상태에 저장한다.

추가로 확인할 사항을 입력해 Codex 리뷰를 다시 요청할 수도 있다.

### 3.6 리뷰 반영 수정

Codex 리뷰가 완료되면 `리뷰 반영 수정 요청`을 사용할 수 있다.

1. 원래 작업 요청, 리뷰 요약, 각 finding, 사용자 추가 지시를 Claude에 전달한다.
2. Claude가 같은 임시 worktree에서 코드를 수정한다.
3. 수정 결과를 새 커밋으로 만들고 diff를 다시 계산한다.
4. 기존 리뷰는 이력으로 보관하고 현재 리뷰는 초기화한다.
5. 사용자는 수정된 결과에 대해 Codex 리뷰를 다시 요청한다.

수정 작업이 실패하거나 중단되면 가능한 경우 직전 검토 버전으로 worktree를 복구한다. 수정은 같은 작업 폴더에서 이어지지만 Claude SDK 세션 자체를 재개하는 방식은 아니며, 필요한 작업 요청과 리뷰 내용을 새 실행에 다시 전달한다.

### 3.7 승인과 반려

**승인**

1. 화면에 표시된 `diffHash`와 `targetSha`가 서버의 값과 같은지 확인한다.
2. 원본 프로젝트가 작업 시작 때의 브랜치와 커밋을 유지하고 있는지 확인한다.
3. `git merge --ff-only`로 결과 커밋을 원본 브랜치에 반영한다.
4. 임시 worktree와 작업 브랜치를 정리한다.

원본 브랜치가 중간에 변경되었거나 새로운 커밋이 생겼다면 자동 승인을 중단한다. 사용자가 변경 상태를 확인한 후 다시 처리해야 한다.

**반려**

1. 반려 사유를 필수로 입력한다.
2. 결과를 원본 프로젝트에 반영하지 않는다.
3. 임시 worktree와 작업 브랜치를 삭제한다.
4. 반려 사유를 작업 기록에 저장한다.

## 4. 구현 기능

### 프로젝트 관리

- 여러 Git 프로젝트 등록 및 탭 전환
- 프로젝트별 마지막 작업 상태 표시
- 동일 경로 중복 등록 방지
- 진행 중인 작업이 있는 프로젝트 제거 차단
- 콘솔 목록에서 프로젝트 제거
- 실제 프로젝트 폴더 보존

### 작업 관리

- 여러 줄 작업 지시 입력
- `Enter`로 전송, `Shift+Enter`로 줄바꿈
- Claude 작업 로그 실시간 표시
- Claude 작업 로그 접기·펼치기
- 작업 중단 및 시간 제한 처리
- 실패·중단 작업의 임시 파일 수동 정리
- 임시 작업 폴더 탐색기로 열기
- 서버 재시작 후 프로젝트와 작업 상태 복원

### Diff 및 리뷰

- 변경 파일 목록과 파일별 diff 표시
- 추가·삭제 라인 구분
- diff SHA-256 해시와 커밋 SHA 고정
- Codex 구조화 리뷰 표시
- 선택 입력을 포함한 재리뷰
- 리뷰를 바탕으로 Claude에 수정 요청
- 수정 전 리뷰 이력 보존

### 모델 및 사용량

- Claude 모델과 effort 선택
- Codex 모델과 effort 선택
- 설정을 `.runtime/settings.json`에 저장
- 작업 시작 시 설정을 작업에 복사하여 실행 중 설정 변경의 영향 차단
- 구현, 수정, 리뷰 실행별 토큰 사용량 표시
- Claude가 보고한 실제 모델·적용 effort 표시
- Codex CLI에 명시적으로 적용한 실행 모델·effort 표시
- Claude 예상 비용 표시

현재 화면에서 제공하는 모델 선택지는 코드에 등록된 목록이다. 실제 사용 가능 여부는 설치된 Claude/Codex 도구 버전과 사용자 계정 권한에 따라 달라질 수 있다. Claude는 SDK 초기화 메시지가 제공한 값을 `실제 모델·effort`로 표시한다. Codex는 CLI 명령에 전달한 값을 `적용 모델·effort`로 표시한다. Codex에서 모델을 명시하지 않고 `기본 모델`을 선택한 경우 CLI가 실제 모델 ID를 이벤트로 제공하지 않으므로 `ID 확인 불가`로 표시한다.

## 6. 실제 사용 예시

예를 들어 기존 프로젝트에 입력값 검증 기능을 추가하려면 다음과 같이 진행한다.

1. 작업 대상 프로젝트가 Git 저장소인지 확인하고 변경사항을 미리 커밋한다.
2. 콘솔을 실행한다.
3. `+ 새 프로젝트`에서 이름과 절대 경로를 등록한다.
4. Claude와 Codex의 모델 및 effort를 선택하고 `설정 저장`을 누른다.
5. 작업 입력창에 다음과 같이 작성한다.

```text
사용자 등록 API에 이메일 형식 검증을 추가해줘.
잘못된 이메일에는 400 응답을 반환하고 관련 테스트도 작성해줘.
```

6. Claude 작업 로그를 확인한다.
7. 작업 완료 후 변경 파일과 diff를 확인한다.
8. 필요하면 `작업 폴더 열기`로 테스트를 직접 실행한다.
9. `Codex 리뷰 요청`을 누른다.
10. 리뷰 지적이 타당하면 추가 요청을 적고 `리뷰 반영 수정 요청`을 누른다.
11. 수정된 diff에 대해 Codex 리뷰를 다시 요청한다.
12. 결과가 적절하면 승인하고, 사용하지 않을 변경이면 사유를 입력해 반려한다.
13. 승인 후 원본 프로젝트에서 커밋과 테스트 결과를 최종 확인한다.

## 7. 보안 및 보호 장치

- **로컬 바인딩**: 백엔드는 `127.0.0.1`에만 바인딩되어 외부 네트워크에서 직접 접속할 수 없다.
- **nonce 토큰**: 서버를 시작할 때 32바이트 임의 토큰을 새로 만들고 모든 보호 API와 WebSocket 연결에서 확인한다.
- **CORS 제한**: 기본적으로 `http://localhost:5173`에서 온 브라우저 요청만 허용한다.
- **파괴적 API 재확인**: 중단, 승인, 반려, 정리, 프로젝트 제거에는 `confirm: true`와 일치하는 ID가 필요하다.
- **불변 대상 확인**: 승인·반려·리뷰 전에 커밋 SHA와 worktree 상태를 검증한다.
- **fast-forward 승인**: 예상하지 못한 merge commit이나 충돌을 자동으로 만들지 않는다.
- **원본 보호**: 반려나 실패 처리에서 원본 프로젝트에 `git reset`, `git restore`, `git clean`을 실행하지 않는다.

이 장치들은 로컬에서 실수나 브라우저의 임의 요청을 줄이기 위한 것이다. 인터넷에 공개하는 서버 수준의 인증 체계를 의미하지는 않는다.

## 8. 로컬 저장 데이터

실행 중 `.runtime` 아래에 다음 데이터가 생성된다.

| 경로 | 내용 |
| --- | --- |
| `.runtime/session.json` | 현재 서버 포트, nonce, 프로세스 정보 |
| `.runtime/projects.json` | 등록된 프로젝트 목록 |
| `.runtime/settings.json` | Claude/Codex 모델 및 effort 설정 |
| `.runtime/tasks.json` | 작업 상태, 이벤트, 리뷰, 사용량 |
| `.runtime/worktrees/` | 승인 또는 반려 전 임시 작업 폴더 |
| `.runtime/reviews/` | diff와 리뷰 스냅샷 |

이 데이터는 해당 콘솔 복사본의 로컬 상태이다. 다른 PC나 다른 폴더로 소스만 복사하면 등록 프로젝트와 작업 이력은 자동으로 따라가지 않는다.

## 9. 테스트

백엔드 단위 테스트:

```powershell
npm test
```

프론트엔드 검사와 빌드:

```powershell
cd frontend
npm run lint
npm run build
```

테스트에는 Git worktree 흐름, 고정된 리뷰 대상 검증, 프로젝트 제거, 설정 저장, 작업 상태 복원, Codex 사용량 파싱 등이 포함되어 있다.

## 10. 현재 제약사항

- 전체 콘솔에서 동시에 하나의 구현·수정 작업만 실행할 수 있다.
- 이전 작업이 승인·반려 또는 정리되지 않으면 다음 작업이 제한될 수 있다.
- 프로젝트 등록 시 Git 저장소의 절대 경로가 필요하다.
- 승인은 파일별 부분 승인이 아니라 작업 전체 단위이다.
- 원본 브랜치가 작업 중 변경되면 자동 승인이 실패한다.
- Claude 수정 요청은 같은 worktree를 사용하지만 이전 Claude 세션을 resume하지는 않는다.
- Codex 리뷰의 토큰 수는 CLI 이벤트에서 수집하며 비용은 표시하지 않는다.
- Claude 비용은 SDK가 제공한 예상값으로 실제 청구 금액과 다를 수 있다.
- 작업 데이터는 JSON으로 보존되지만 전체 작업 이력을 조회하는 별도 화면은 아직 없다.
- 콘솔에서 프로젝트를 제거해도 실제 프로젝트 폴더는 삭제되지 않는다.
